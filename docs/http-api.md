# Адреса HTTP API

Внешний префикс CMS API — `/api`. Базовый адрес локального API:
`http://localhost:8080/api`. Во всех примерах документации запросы содержат полный
путь от корня домена.

Префикс `/api` включён в kernel `v0.4.0`, закреплённый в Starter. Обычная
Docker-сборка использует эти адреса без локального Go workspace или `replace`.

| API | Внешние адреса |
| --- | --- |
| Вход и выход | `POST /api/auth/login`, `POST /api/auth/logout` |
| Админка | `/api/admin/...` |
| Сайты, ресурсы и модули управления | `/api/sites/...`, `/api/site-profiles` |
| Файловый менеджер и media | `/api/files/...`, `/api/media/...` |
| Системное администрирование | `/api/administration/...` |
| Публичные данные сайта и меню | `GET /api/site`, `GET /api/menu` |
| Поиск | `GET /api/search?q=...` |
| Публичные формы | `GET /api/forms/{code}`, `POST /api/forms/{code}/submit`, `GET /api/forms/{code}/results` |
| Корневой ресурс | `GET /api/` (также `/api`) |
| Ресурс или элемент библиотеки | `GET /api/{resource-path}` |
| Данные runtime | `GET /api/_cms/runtime` |

Публичные API выбирают сайт по домену запроса и соблюдают его права доступа.
Отсутствие обязательного входа в админку не делает закрытый сайт или ресурс
публичным. Управляющие API сохраняют обязательную аутентификацию и свои проверки
прав независимо от публичных маршрутов.

## Путь страницы и адрес API

Путь ресурса `/about` хранится без префикса API. Для получения его JSON клиент
запрашивает `/api/about`; поля путей в ответах, ссылки меню, поисковой выдачи и SEO
остаются адресами страниц сайта. Аналогично обрабатываются LibraryItem.
Внутреннее HTTP-перенаправление типа ResourceLink ведёт на `/api/{target-path}`,
а Link сохраняет заданный внешний URL.

Прежние API-адреса `/site`, `/menu`, `/search`, `/forms/...`, `/_cms/runtime`
и выдача ресурсов вне `/api` больше не обслуживаются: backend возвращает 404,
без алиасов и перенаправлений. `/api/api/...` также не обслуживается.

Исключения: доставка файлов по `/_cms/files/...` (включая подписанные ссылки)
и проверка запуска `/healthz` сохраняют свои адреса. Базовые URL файловых дисков
и `ADMIN_API_TARGET` указывают на origin backend без добавления `/api`.

## Регистрация маршрутов модулей

`httptransport.Registrar` принимает пути относительно `/api`: например,
`Pattern: "/search"` публикуется как `/api/search`. `Group` и `Mount` используют
ту же базу. Сервер снимает внешний префикс ровно один раз перед вызовом
публичного обработчика; `request.URL.Path` внутри него содержит относительный
к API путь. Префикс для генерируемых API-ссылок задан константой
`httptransport.APIPrefix`.

API-пространства `/auth`, `/admin`, `/sites`, `/site-profiles`, `/files`, `/media`,
`/administration`, `/_cms` и `/api` зарезервированы относительно общего префикса.
Модуль не может зарегистрировать в них литеральный маршрут или mount.
Запросы внутри этих пространств не передаются публичным ресурсам, включая
неизвестные адреса административных операций.

Site-management contributions сохраняют базу `/api/sites/{siteID}/{module}`.
Их handler объявляет только оставшийся относительный путь; например, Mail
объявляет `/send`, а внешний запрос идёт на `/api/sites/{siteID}/mail/send`.

## Динамические зоны виджетов

Публичный ответ ресурса содержит `widgets` как объект `код зоны → массив виджетов`.
Коды определяются шаблоном; названия и размеры контейнеров в ответ не включаются:

```json
{"widgets":{"main":[],"aside":[],"footer":[]}}
```

Объявленные зоны присутствуют даже пустыми. Если зон нет, используется
`{"widgets":{"default":[]}}`. При наличии зон дополнительный `default` включается
только при наличии собственных виджетов или виджетов исчезнувших зон. Выключенные
виджеты сохраняют контейнер, но не рендерятся. Без выбранного шаблона `widgets` — `{}`.
Порядок ключей JSON не задаёт разметку страницы.

В management metadata `widget_areas` — упорядоченный массив объектов
`{code, label, admin_span, supports_resource_widgets}`. `area` в сохранённой привязке
остаётся исходным кодом. Админка помещает привязки отсутствующих редактируемых зон
в `default`; только явный перенос меняет их код. Полная перестановка передаёт
неизменённые коды остальных привязок и текущий `expected_version`.
