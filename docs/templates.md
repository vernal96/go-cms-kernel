# Разработка шаблонов страниц

Шаблон страницы — `template.Definition` в `kernel.Profile.Templates`. Он задаёт поля ресурса и расположение виджетов. Это декларация backend, а не HTML-файл и не исполняемый Go `html/template`: публичный API отдаёт данные ресурса и виджетов, а frontend выбирает способ отображения. Шаблоны писем Mail и строки интерполяции SEO — отдельные механизмы ([Mail](modules/mail/entities.md), [SEO](modules/seo/entities.md)).

Пакет: `github.com/vernal96/go-cms-kernel/modules/core/template`. Для полей и виджетов также нужны `modules/core/field`, `modules/core/widget`, `modules/core/widgets`. Шаблон добавляют в профиль вместе с обязательными Core и Admin. После изменения определения перезапустите приложение или пересоберите runtime сайта штатным способом: итоговый каталог шаблонов и виджетов создаётся для сайта при сборке runtime.

## Полный пример

Добавьте в `kernel.Profile`:

```go
Templates: []template.Definition{{
    Code: "article",
    Label: "Статья",
    Icon: "document",
    Fields: []field.Definition{
        {Key: "lead", Type: field.TypeTextarea, Label: "Вступление"},
    },
    EditorTabs: []field.EditorTab{
        {Code: "content", Label: "Содержание", Fields: []string{"lead"}},
    },
    Layout: template.Layout{
        {
            Code: "main", Label: "Основная область", AdminSpan: 16,
            Items: []template.Item{
                template.Widget{Widget: widgets.Content},
                template.ResourceWidgets{},
            },
        },
        {
            Code: "aside", Label: "Боковая область", AdminSpan: 8,
        },
    },
}},
```

При этом `widgets.Content` — `widget.Ref` встроенного Core. В `main` сначала выводится статический виджет контента, затем ресурсные виджеты, которые редактор разместил в этой зоне. `aside` с отсутствующим `Items` целиком отдаётся редактору. `lead` хранится как поле ресурса; вкладка группирует поле только в редакторе. Код шаблона выбирается в ресурсе через `template_code` (см. [Core API](modules/core/api.md)).

## Параметры `template.Definition`

| Параметр | Назначение и ограничения |
| --- | --- |
| `Code template.Code` | Уникальный непустой код в каталоге профиля, без пробелов по краям. Стабильный идентификатор, на который ссылаются ресурсы. |
| `Label string` | Непустое название для редактора, без пробелов по краям. |
| `Icon string` | Необязательный код иконки. Пробелы по краям удаляются; пробелы и символы `/` и `\` внутри запрещены. |
| `Fields []field.Definition` | Дополнительные сохраняемые поля ресурса этого шаблона. Каждый тип должен быть зарегистрирован в каталоге полей; см. [проверки полей](modules/core/fields.md). |
| `EditorTabs []field.EditorTab` | Необязательная группировка `Fields` в редакторе. Если табы заданы, каждое поле должно входить ровно в один таб; неизвестные и повторные ключи отклоняются. Не меняет сохранение и публичность значения. |
| `Layout template.Layout` | Упорядоченные зоны и элементы внутри них. При отсутствии зон доступна стандартная зона `default`. |

Для каждого `field.Definition` используются `Key` (уникальный ключ), `Type` (тип значения), `Label`, `Required`, `Validators`, `Options`, `Editor`, `VisibleWhen`. `Public` имеет смысл для параметров сайта `Profile.Params`; не используйте его как переключатель публичности поля шаблона. Типы и опции подробно перечислены в [справочнике полей](modules/core/fields.md) и [контракте проверки](field-validation.md). `field.EditorTab` содержит `Code`, `Label`, `Fields []string` с ключами полей; порядок табов и ключей задаёт порядок в редакторе.

## Параметры зоны `template.Area`

| Параметр | Назначение и ограничения |
| --- | --- |
| `Code widget.AreaCode` | Уникален внутри шаблона; формат `[a-z][a-z0-9_-]*`. Код `default` зарезервирован. |
| `Label string` | Непустое название без пробелов по краям. |
| `AdminSpan int` | Ширина контейнера в административной сетке от 1 до 24; `0` означает 24. На узком экране зона занимает всю строку. На публичную сетку и `Columns` виджетов не влияет. |
| `Items []template.Item` | Порядок статических `template.Widget` и слота `template.ResourceWidgets{}`. `nil` подразумевает один слот; явный пустой список означает пустую зону без добавления ресурсных виджетов. |

`ResourceWidgets{}` обозначает позицию, в которую подставляются сохранённые привязки виджетов текущего ресурса. В одной зоне допустим максимум один слот. Если слот отсутствует, редактор не может разместить ресурсные виджеты в этой зоне. `default` доступен как восстановительная зона даже после удаления объявленной зоны: старые привязки выводятся там, а их исходный код зоны сохраняется. Если объявленных зон нет, `default` называется «Страница сайта»; если зоны есть, он показывается последним при наличии виджетов. Подробнее о поведении редактора — [зоны виджетов](widget-areas.md).

## Параметры статического `template.Widget`

| Параметр | Назначение и ограничения |
| --- | --- |
| `Widget widget.Ref` | Ссылка на зарегистрированный виджет, например `widgets.Content` или `widgets.HTML`; пустая/недоступная ссылка отклоняется при сборке. |
| `View widget.View` | Необязательный вариант представления. Нулевое значение — default; выбранный view должен принадлежать этому виджету и быть доступен в профиле. |
| `Columns int` | Ширина виджета от 1 до 12; `0` означает 12. |
| `MarginTop int`, `MarginBottom int` | Отступы от 0 до 3. |
| `Params map[string]any` | Статические значения параметров виджета. Ключи, типы и обязательность определяет `widget.Definition.Fields` конкретного виджета. |
| `ParamBindings widget.ParamBindings` | Привязка параметра к свойству или полю текущего ресурса. Ключ — параметр виджета, значение — `widget.ResourceProperty(key)` или `widget.ResourceField(key)`. Тип и множественность источника должны совпадать с параметром. |

Статический виджет всегда включён. `Items` и виджеты компилируются при сборке runtime сайта; некорректный view, неизвестный параметр или неподходящая привязка прерывают сборку. `Params` задаёт фиксированное значение, а `ParamBindings` — значение из текущего ресурса во время вывода. Например:

```go
template.Widget{
    Widget: widgets.HTML,
    Params: map[string]any{"html": "<p>Постоянный текст</p>"},
    Columns: 6,
    MarginTop: 1,
}
```

Для привязки нужен виджет, чей параметр имеет тот же тип, что и источник. Например, у собственного строкового параметра `heading` можно указать `ParamBindings: widget.ParamBindings{"heading": widget.ResourceProperty("title")}`. Доступные свойства: `title`, `menu_title`, `slug`, `path`, `annotation`, `content`, `image_media_id`; собственное поле задаётся как `widget.ResourceField("lead")`, если оно объявлено в `Fields` шаблона. Не передавайте одновременно статический `Params["heading"]` и привязку того же параметра.

## Проверка

После добавления определения соберите приложение и откройте метаданные редактора и ресурс с `template_code`. Ошибка компиляции профиля показывает код шаблона и проблемную зону или поле. В API проверьте порядок статических и ресурсных виджетов, размещение по зонам и значения привязок на двух ресурсах с разными данными. Описание API и редактора — в [Core](modules/core/README.md).
