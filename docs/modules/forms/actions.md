# Типы действий Forms

`ActionType` описывает обработчик, который Forms запускает для подходящего события результата. Встроенный тип `mail` отправляет письмо через модуль Mail; проектные модули могут зарегистрировать собственные типы, например для обращения во внешний сервис. Реализация действия и её зависимости принадлежат модулю, который её объявляет.

## Контракт действия

Тип реализует `forms.ActionType`:

- `Code()` возвращает уникальный код, сохранённый в `Action.ActionType`.
- `Metadata()` описывает тип в редакторе действий. `Metadata.Code` должен совпадать с `Code()`, а `Label` должен быть непустым. `Fields` и `EditorCode` используются клиентом как метаданные редактора.
- `ValidateConfig` проверяет JSON-конфигурацию действия при создании или изменении action. Здесь нужно проверять обязательные параметры и их формат; повторно проверьте критичные для выполнения предпосылки в `Execute`, поскольку внешняя система также может измениться.
- `Execute` выполняет действие с сохранённой конфигурацией и контекстом исполнения. При успехе можно вернуть `ActionExecutionResult.ExternalReference`; Forms сохраняет эту ссылку в исполнении.

Код типа должен быть непустым и без пробелов по краям. Повторная регистрация кода, несовпадающий код в metadata и регистрация после финализации runtime завершают сборку ошибкой. У типа нет отдельного API для изменения списка его кодов после регистрации.

## Контекст исполнения и границы сайта

`ActionExecutionContext` содержит:

| Поле | Содержание |
| --- | --- |
| `Execution` | Конкретное исполнение, включая его `ID`, `SiteID`, `ResultID`, тип, триггер, число попытки и статус. Конфигурация передаётся отдельным аргументом `Execute`. |
| `Result` | Снимок результата с `SiteID`, кодом формы и текущим бизнес-статусом. |
| `Values` | Значения полей результата с кодом и метаданными поля. |
| `Uploads` | `UploadAccessor` для метаданных файлов и открытия их содержимого по коду поля и позиции. |

Forms создаёт отдельный runtime и worker для каждого сайта. Внешние запросы должны использовать зависимости, созданные для этого runtime, и данные только соответствующего сайта. Не храните выбранный сайт или текущий результат в глобальном изменяемом состоянии. Убедитесь, что `Execution.SiteID` и `Result.SiteID` соответствуют ожидаемой области интеграции, прежде чем обращаться к внешней системе.

`ActionExecution.ID` — стабильный идентификатор записи исполнения, общий для его повторных попыток. Обработка доставляется как минимум один раз: процесс может завершиться после успешного внешнего вызова, но до сохранения `succeeded`, и Forms повторит вызов. Передавайте `Execution.ID` внешнему сервису как ключ идемпотентности (при необходимости вместе с `SiteID`) или реализуйте эквивалентную дедупликацию. Не полагайтесь на то, что HTTP-вызов произойдёт ровно один раз.

`Uploads.Open(ctx, fieldCode, position)` возвращает поток, который вызывающий код обязан закрыть. Метаданные не раскрывают внутреннюю ссылку spool. При триггере `status_changed` встроенное действие `mail` запрещает вложения из временных upload-файлов; собственное действие должно учитывать, что доступность таких данных зависит от жизненного цикла результата и других исполнений.

## Ошибки и повторы

Возвращайте `*forms.ActionError`, если классификация ошибки известна:

- `Retryable: true` означает временный сбой, который стоит повторить: например, таймаут или временная недоступность внешнего API.
- `Retryable: false` означает терминальную ошибку: например, отклонённая или некорректная конфигурация, отсутствующее обязательное значение либо отказ, который повторный запрос не исправит.
- `Code` — короткий стабильный код для журналов и диагностики. Не помещайте туда секреты или персональные данные.
- `Err` сохраняет причину для диагностики. Текст ошибки записывается в `SafeError`, поэтому возвращайте безопасное сообщение и не включайте в него токены, адреса с секретами или содержимое формы.

Обычная ошибка, не обёрнутая в `ActionError`, считается временной с кодом `temporary_failure`. Поэтому для постоянных ошибок обязательно возвращайте терминальный `ActionError`, иначе бессмысленные повторы продолжатся до исчерпания лимита. Лимит попыток задаётся `forms.Config.ActionMaxAttempts`; после последней попытки исполнение становится `failed`, даже если ошибка помечена повторяемой. До этого состояние будет `retryable`.

Успешный результат переводит исполнение в `succeeded`. Терминальная ошибка переводит его в `failed`; Forms не повторяет такое исполнение. Эти технические состояния не заменяют бизнес-статус результата.

## Триггер смены статуса

Action может запускаться на `submitted` или `status_changed`. Для второго типа `Trigger.From` и `Trigger.To` — необязательные коды статусов формы. Пустое значение означает любое исходное или целевое состояние соответственно. Например, этот action запускается только при переходе в `sent_to_service`:

```go
forms.Action{
	Code:      "send_appeal",
	Name:      "Передать обращение",
	Enabled:   true,
	Trigger: forms.Trigger{
		Type: forms.TriggerStatusChanged,
		To:   "sent_to_service",
	},
	ActionType: "appeals.forward",
	Config:     json.RawMessage(`{"endpoint":"appeals"}`),
}
```

Коды из `from_status` и `to_status` должны принадлежать статусам этой формы; неизвестный код отклоняется при валидации action. При смене статуса Forms выбирает включённые actions, чьи ограничения совпали с фактическим переходом, и создаёт исполнения в рамках той же транзакции, что и изменение результата. Код `from_status`/`to_status` описывает фильтр запуска, а не изменение бизнес-статуса самим action.

## Регистрация из проектного модуля

Зарегистрируйте тип как runtime contribution модуля, который зависит от `forms.ModuleCode`. Contribution применяется при создании каждого `SiteRuntime`, до финализации реестра Forms. Это позволяет action использовать сервисы целевого сайта; не регистрируйте его в глобальном реестре или из HTTP-обработчика.

Forms публикует `forms.ActionRegistrar`. Схема contribution и минимальная реализация интерфейса приведены в разделе [Runtime contributions: Forms](../../contributions.md#runtime-contributions-forms). Для внешнего вызова дополните action собственным клиентом/интерфейсом, передавайте стабильный ключ идемпотентности и преобразуйте временные и постоянные ошибки в `ActionError` с соответствующим `Retryable`.
