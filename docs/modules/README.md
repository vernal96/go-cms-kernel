# Справочник модулей

Справочник описывает шесть встроенных модулей kernel. Примеры подключения ниже используют API kernel `v0.4.0`. У каждого модуля своя папка с краткой страницей-оглавлением и отдельными страницами по темам: **Сущности**, **API**, **Виджеты**, а при наличии — **Поля**, **Команды** и **Фоновые задачи**.

В Starter подключены только `core` и `admin` ([объявление профиля](https://github.com/vernal96/go-cms/blob/main/backend/internal/profiles/starter/profile.go)). Остальные модули подключаются в профиле приложения вместе с необходимыми зависимостями и инфраструктурой. Пошаговые примеры для каждого модуля и перечень зависимостей находятся в [руководстве по подключению](adding-modules.md).

## Модули

- [Core](core/README.md) — сайты, ресурсы, файлы, медиа, учётные записи, общие поля и виджеты.
- [Admin](admin/README.md) — административная сессия, профиль пользователя, управление пользователями, группами и навигацией.
- [Forms](forms/README.md) — конструктор форм, публичная отправка, результаты и действия.
- [Mail](mail/README.md) — шаблоны, очередь доставки и история писем.
- [Search](search/README.md) — публичный поиск по ресурсам сайта.
- [SEO](seo/README.md) — SEO-метаданные в редакторе и публичной проекции ресурса.

## Подключение модулей

Обязательный `core` должен быть первым; `admin` также обязателен. Остальные зависимости указываются явно. Например, `forms` требует `mail`:

```go
Modules: []kernel.Module{
    core.New(core.Config{}),
    admin.New(),
    mail.New(mailConfig),
    forms.New(formsConfig),
}
```

`mailConfig` и `formsConfig` здесь — заранее объявленные `mail.Config` и `forms.Config` с требуемыми лимитами и настройками. Нулевая конфигурация Mail или Forms не является готовой конфигурацией запуска. Подробнее: [параметры и проверки профиля](../profiles.md#типизированные-параметры-модулей).

Точные database factory, транспорт, CAPTCHA-провайдеры, файловые подключения и конфигурация предоставляются приложением. Добавление модуля в профиль само по себе не настраивает эти зависимости.

## О структуре страниц

API-пути приводятся относительно соответствующего обработчика, если не указан полный путь. Фактический базовый префикс зависит от HTTP-сборки приложения. Примеры management API требуют аутентификацию и права; публичные маршруты используют сайт, определённый обычным механизмом маршрутизации CMS. Общие типы полей и базовые виджеты принадлежат `core`.
