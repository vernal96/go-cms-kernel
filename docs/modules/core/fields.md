# Core: типы полей

Каталог `core.field` предоставляет стандартные типы для полей шаблонов, ресурсов и других модулей. Определение поля задаёт код, тип, подпись, обязательность, типизированные валидаторы и метаданные редактора.

| Код | Применение |
| --- | --- |
| `string`, `textarea`, `email`, `phone` | Текстовые значения; email проверяется как адрес, телефон имеет встроенную проверку E.164 |
| `int`, `float`, `checkbox` | Числа и логическое значение |
| `radio`, `select` | Выбор значения из `choices` |
| `file`, `media` | Ссылка на файл из разрешённых дисков или на media |
| `json` | Структурированные JSON-значения |
| `repeater` | Повторяемые вложенные значения с дочерними определениями |

Пример поля, объявляемого в шаблоне (импортируйте `modules/core/field/validation`):

```go
field.Definition{
    Key:   "summary",
    Type:  field.TypeTextarea,
    Label: "Краткое описание",
    Validators: []field.ValidatorDefinition{validation.MaxLength(255)},
}
```

Для `radio` и `select` в `Options` передаётся список choices. Файловое поле настраивается через `field.FileOptions`: диск и код настроек обязательны, `VirtualPath` задаёт путь назначения новых загрузок, а MIME-типы и множественность необязательны. Поле хранит ID отдельной `Media` для каждого выбранного файла. Тип значения отвечает за нормализацию/валидацию, а `Editor`/metadata описывают его административное представление. Поля настроек сайта `Profile.Params` — отдельный контракт, описанный в [профилях](../../profiles.md).

## Файловое поле

`Disk` должен быть объявленным диском, `VirtualPath` — допустимым виртуальным путём на нём, а `SettingsCode` — кодом схемы настроек медиа, объявленной в `core.Config.MediaSettings`. Компиляция профиля проверяет эти опции и наличие схемы. `MIMETypes` принимает MIME-типы и шаблоны наподобие `image/*`; сервер проверяет фактический MIME и диск каждого выбранного файла при сохранении. Интерфейс также фильтрует неподходящие файлы до загрузки, но серверная проверка остаётся обязательной. `Multiple: false` хранит одно значение Media ID; `Multiple: true` — упорядоченный список таких ID.

Путь назначения влияет только на новые загрузки. Перед загрузкой интерфейс создаёт виртуальный путь на заданном диске, если он ещё не существует, и загружает файл туда. Открытый из поля файловый менеджер позволяет выбрать существующий файл из любого каталога того же диска. Это позволяет переиспользовать файл, не ограничивая выбор папкой загрузки. Пустые или неизвестные обязательные параметры, недопустимый виртуальный путь и неизвестный `SettingsCode` приводят к ошибке компиляции профиля; при сохранении backend отклоняет ссылку на другой диск или файл с MIME вне `MIMETypes` как ошибку валидации поля.

Схемы `MediaSettings` содержат только метаданные: поля со ссылками на сущности, включая `file`/`media` внутри повторителей и списков, отклоняются при компиляции. При смене текущего файла Media, редактировании изображения и восстановлении оригинала сервер повторно проверяет Disk/MIME по текущим схемам всех сохранённых файловых полей сайта, ресурса, виджета и модулей. Несовместимая смена отклоняется до изменения Media и очистки старого файла.

Результаты Forms используют ограничения файловых ссылок, сохранённые при отправке формы; изменение текущих полей формы не меняет этот исторический контракт.

Пример объявления поля и отдельного набора метаданных:

```go
import (
	kernel "github.com/vernal96/go-cms-kernel"
	"github.com/vernal96/go-cms-kernel/modules/admin"
	"github.com/vernal96/go-cms-kernel/modules/core"
	"github.com/vernal96/go-cms-kernel/modules/core/field"
	"github.com/vernal96/go-cms-kernel/modules/core/media"
)

var Profile = kernel.Profile{
	Code: "editorial",
	Modules: []kernel.Module{
		core.New(core.Config{MediaSettings: []media.SettingsDefinition{{
			Code: "site_logo",
			Fields: []field.Definition{
				{Key: "title", Label: "Название", Type: field.TypeString},
				{Key: "alt", Label: "Альтернативный текст", Type: field.TypeString},
				{Key: "description", Label: "Описание", Type: field.TypeTextarea},
			},
		}}}),
		admin.New(),
	},
	Params: []field.Definition{{
		Key: "logo", Label: "Логотип", Type: field.TypeFile, Required: true,
		Options: field.FileOptions{
			Disk: "public", VirtualPath: "site/logo", SettingsCode: "site_logo",
			MIMETypes: []string{"image/*"},
		},
	}},
}
```

Если profile содержит `EditorTabs`, включите ключ `logo` ровно в один таб. Ключи `title`, `alt` и `description` сами по себе не имеют специального поведения: это обычные поля схемы. Значения схемы хранятся у конкретной Media отдельно от состояния изображения, поэтому настройки и редактирование изображения одной плитки не изменяют другую Media, даже если обе ссылаются на один исходный файл. Подробнее о GET/PUT настроек, валидации и конфликте версии — в [справочнике API Core](api.md#изображения-media-и-site-menu).

В админке одиночное и множественное файловые поля используют плитки без папок. Одиночная плитка занимает всю доступную ширину. В множественном режиме плитки можно переставлять перетаскиванием; порядок сохраняется как порядок массива Media ID. Клик по полю открывает файловый менеджер. Контекстное меню позволяет редактировать поддерживаемое изображение, открыть метаданные, убрать значение из формы или запросить физическое удаление файла. «Удалить» меняет только черновик формы и сохраняется вместе с формой; физическое удаление выполняется сразу после подтверждения и проверки всех ссылок. Контракт и состояния физического удаления описаны в [руководстве по удалению файлового поля](file-field-deletion.md).

Скомпилированный валидатор модуля явно задаёт `Scope() field.ValidatorScope`: `ValidatorScopeValue` проверяет значение целиком, `ValidatorScopeItems` — каждый элемент множественного поля. Обязательные параметры проверок не принимают `null`; целые числа в `in`/`not_in` сохраняют точность при JSON-сериализации и загрузке настроек.

Подробный контракт, каталог и пример расширения модулем: [проверки полей в kernel](../../field-validation.md).
