# Файловые поля: окончательное удаление

`TypeFile` хранит ID `Media`, созданной для конкретного выбора. Метаданные и
редактор изображения меняют только эту Media. `Disk`, `VirtualPath` и
`SettingsCode` обязательны; путь задаёт место загрузки, выбор существующих файлов
разрешён на всём диске. `Multiple` задаёт одиночное значение или упорядоченный
массив Media ID. Обычное удаление плитки меняет форму до её сохранения.

## Немедленное действие

После подтверждения клиент вызывает:

```http
POST /api/sites/{siteID}/media/{mediaID}/delete-file
Content-Type: application/json

{"expected_file_id":123,"expected_updated_at":"2026-10-09T10:00:00Z"}
```

Предусловия берутся из текущей Media. Сервер требует доступ на изменение сайта,
право удаления File и Media, а для сохранённой ссылки — право изменения её
владельца. Допустимо ноль или одно сохранённое вхождение `TypeFile`. Любая другая
ссылка этой Media, включая галерею, image/avatar и результаты Forms, либо другая
Media на любом File удаляемого дерева блокирует действие.

Дерево начинается от текущего `Media.FileID`. Удаление оригинала охватывает его
производные; удаление производного файла сохраняет оригинал. Сервер обнаруживает
владельца и точный путь из нормализованного индекса. Вложенная строка repeater
сохраняется, а массив файлов сокращается с сохранением порядка и пересчётом путей.
Это специальное действие может очистить обязательный файловый выбор; последующее
чтение/reload остаётся допустимым, обычное сохранение формы проверяет `Required`.

## Ответ и физическая очистка

SQL-транзакция сохраняет изменённого владельца, его lifecycle/history/outbox и
durable operation с manifest физических объектов. Site runtime сначала
подготавливается и публикуется после commit.

Подготовка владельца-сайта захватывает блокировку Catalog до repository cache
locks, как и обычные изменения сайта. Транзакция повторно проверяет точное
вхождение; конфликт отменяет подготовку и не публикует новый runtime.

Байтам на диске не назначается несуществующая распределённая ACID-транзакция:
физическая очистка выполняется
после commit, сначала синхронно, затем повторяется application worker при сбое.

```json
{
  "operation_id":"opaque-id",
  "status":"completed",
  "media_id":45,
  "deleted_file_ids":[123],
  "cleared_reference":{
    "owner_kind":"site",
    "owner_id":7,
    "site_id":7,
    "container":"settings",
    "path":["portals","1","icon"],
    "media_id":45,
    "target":"file",
    "owner_version":8
  },
  "status_url":"/api/sites/7/media-file-deletions/opaque-id"
}
```

`200` означает завершённую физическую очистку. `202` с `status:"pending"` означает,
что сохранённая ссылка уже очищена, но удаление байтов ещё ожидает повторения;
клиент обязан показать это состояние. При несохранённом выборе
`cleared_reference:null`. Опрос:

```http
GET /api/sites/{siteID}/media-file-deletions/{operationID}
```

Возвращает `200` с текущим `pending`/`completed`. Worker повторяет сохранённые
операции после запуска и каждые пять секунд; уже отсутствующие объекты считаются
удалёнными. Прямой публичный URL может оставаться действующим до завершения
physical cleanup при `pending`. Новый запрос удаления уже удалённой Media — `404`;
статус прежней операции остаётся доступен по `operation_id`.

Ошибки: `409 media_file_in_use` при других ссылках;
`409 media_file_delete_conflict` при изменившейся Media/владельце;
`403` при недостаточных правах; `422` при отсутствии предусловий или неподдерживаемом
владельце. Общий FileExplorer cascade остаётся отдельной операцией.

## Владельцы дополнительных модулей

Runtime модуля может предоставлять
`FileOccurrenceOwners() []media.FileOccurrenceOwner`. Владелец объявляет стабильный
`Kind`, право изменения и `ClearFileOccurrence`; он изменяет своё доменное значение
в том же unit of work и не делает отдельный commit. PostgreSQL adapters используют
`mediaoccurrence.Replace` для индекса на всех поддерживаемых write/delete paths
и `mediaoccurrence.Transaction` для mutation. Последний требует тот же Pool, что
и Core transaction; отдельная база данных не поддерживает атомарное удаление
таким контрактом. Защищённые occurrences имеют target `media` и всегда блокируют
удаление; отсутствие clear-провайдера не разрешает обходить ссылку.
